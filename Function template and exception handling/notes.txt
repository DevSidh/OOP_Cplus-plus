===============================================================================
                    C++ FUNCTION TEMPLATES AND EXCEPTION HANDLING
===============================================================================

1. FUNCTION TEMPLATES
===============================================================================



1.1 BASIC FUNCTION TEMPLATES
----------------------------
Function templates allow you to write generic functions that work with any data type.

Syntax:
    template <typename T>
    return_type function_name(parameters) {
        // function body
    }

Example:
    template <typename T>
    T add(T a, T b) {
        return a + b;
    }

    int main() {
        cout << add(5, 3);           // T = int, output: 8
        cout << add(2.5, 3.5);       // T = double, output: 6
        cout << add("Hello", " World"); // T = string, output: Hello World
        return 0;
    }

1.2 MULTIPLE TEMPLATE PARAMETERS
---------------------------------
You can have multiple template parameters.

Example:
    template <typename T, typename U>
    void print_pair(T first, U second) {
        cout << first << " " << second << endl;
    }

    int main() {
        print_pair(10, "hello");     // T=int, U=string
        print_pair(3.14, 42);        // T=double, U=int
        return 0;
    }

1.3 DEFAULT TEMPLATE ARGUMENTS
-------------------------------
You can provide default types for template parameters.

1.4 ALLOW ALL (VARIADIC AND GENERIC LAMBDA / TEMPLATE TECHNIQUES)
-----------------------------------------------------------------
To "allow all" types or an arbitrary number of arguments, use variadic templates
or generic lambdas (C++14+). These let functions accept any number and mix of
types.

Example (variadic template):
        template<typename... Args>
        void log_all(Args&&... args) {
                (std::cout << ... << args) << std::endl; // fold-expression (C++17)
        }

Example (generic lambda):
        auto sum = [](auto... values) {
                return (values + ...); // works for types that support +
        };

1.5 DIFF BETWEEN auto AND template
----------------------------------
Both 'auto' (especially in C++14+ generic lambdas and auto function parameters in C++20) and templates provide type-generic code, but they differ in intent, syntax and capabilities:

- Declaration style:
    - template: write a template header: template<typename T> ...
    - auto: use 'auto' for type deduction (variables, return type, or generic lambda parameters)

- Use cases:
    - template: for generic functions, classes, and full control over template parameters (multiple parameters, defaults, specialization).
    - auto: lightweight deduction for variables, return types, and concise generic lambdas.

- Syntax example:
    template<typename T>
    T add_t(T a, T b) { return a + b; }

    auto add_a = [](auto a, auto b) { return a + b; };

- Differences:
    - Templates can be specialized/overloaded and have explicit template parameters; auto-deduced parameters cannot be explicitly specified.
    - Templates support non-type and template template parameters; auto does not.
    - Templates are available in older standards; generic 'auto' parameters require C++14/20 features.
    - Error messages: template instantiation errors often point into template code; auto-deduction in lambdas can be simpler to read.

- When to prefer which:
    - Use templates when you need full generic programming features, specializations, or library interfaces.
    - Use auto/generic lambdas when you want concise, local generic behaviors or simpler type deduction.

Short example showing both together:
    template<typename T>
    T multiply(T a, T b) { return a * b; }

    auto multiply_generic = [](auto a, auto b) { return a * b; };

Both can be used similarly, but templates offer more extensibility.

Notes:
        - Use perfect forwarding (Args&&) when forwarding values to preserve rvalue/lvalue.
        - Variadic templates can be combined with type traits to constrain allowed types.

1.5 DIFFERENCES (FUNCTION TEMPLATES VS OVERLOADING VS MACROS)
------------------------------------------------------------
- Function templates generate type-safe functions at compile time; macros perform
    blind textual substitution (no type checking).
- Templates support type deduction, specialization, and SFINAE/constraints; macros
    do not.
- Function overloading chooses the best-matching function among candidates;
    templates participate in overload resolution and can provide generic fallbacks.
- Prefer templates for generic code; use macros only for conditional compilation or
    simple constants/guards.


Example:
    template <typename T = int>
    T multiply(T a, T b) {
        return a * b;
    }

    int main() {
        cout << multiply(5, 3);      // Uses default int
        cout << multiply(2.5, 3.5);  // Explicitly uses double
        return 0;
    }

1.4 NON-TYPE TEMPLATE PARAMETERS
---------------------------------
Templates can also accept constant values as parameters.

Example:
    template <typename T, int size>
    void fill_array(T arr[]) {
        for (int i = 0; i < size; i++) {
            arr[i] = i * 2;
        }
    }

    int main() {
        int arr[5];
        fill_array<int, 5>(arr);
        for (int val : arr) cout << val << " ";  // Output: 0 2 4 6 8
        return 0;
    }

1.5 FUNCTION TEMPLATE SPECIALIZATION
-------------------------------------
You can create specialized versions of templates for specific types.

Example:
    template <typename T>
    void print_type(T value) {
        cout << "Generic template" << endl;
    }

    // Specialization for int
    template <>
    void print_type<int>(int value) {
        cout << "Specialized for int: " << value << endl;
    }

    int main() {
        print_type(3.14);      // Generic template
        print_type(42);        // Specialized for int
        return 0;
    }

1.6 VARIADIC TEMPLATES (C++11)
------------------------------
Templates that can accept variable number of arguments.

Example:
    template <typename T>
    void print_args(T single) {
        cout << single << endl;
    }

    template <typename T, typename... Args>
    void print_args(T first, Args... rest) {
        cout << first << " ";
        print_args(rest...);
    }

    int main() {
        print_args(1, 2, 3, 4, 5);  // Output: 1 2 3 4 5
        return 0;
    }

1.7 MAIN DIFFERENCES: AUTO vs TEMPLATE
---------------------------------------
AUTO (Type Deduction):
  - Deduces type at compile-time from the initializer
  - Only for variables, not for functions
  - Fixed type once deduced (no generalization)
  - Narrower scope of use
  - Type is determined by single initialization

TEMPLATE (Generic Functions/Classes):
  - Deduces type at compile-time during instantiation
  - Can be used for functions, classes, and variables
  - Creates generic code that works with multiple types
  - Broader scope - can be called with different types
  - Creates separate code for each type used (code bloat potential)

Example Comparison:
    // Using auto - type fixed at compile-time
    auto x = 5;         // x is int
    auto y = 3.14;      // y is double
    // x cannot be used with different types later
    
    // Using template - generic across types
    template <typename T>
    T max_value(T a, T b) {
        return (a > b) ? a : b;
    }
    
    max_value(5, 10);        // Works with int
    max_value(3.14, 2.71);   // Works with double
    max_value("a", "b");     // Works with string
    
Key Difference:
  - auto: one variable, one type
  - template: one function/class, many types

===============================================================================
2. EXCEPTION HANDLING
===============================================================================

2.1 BASIC TRY-CATCH BLOCKS
---------------------------
Used to catch and handle runtime errors.

Syntax:
    try {
        // Code that may throw an exception
    }
    catch (exception_type e) {
        // Handle the exception
    }

Example:
    int main() {
        try {
            int arr[5] = {1, 2, 3, 4, 5};
            cout << arr[10];  // Out of bounds
        }
        catch (exception &e) {
            cout << "Exception caught!" << endl;
        }
        return 0;
    }

2.2 THROWING EXCEPTIONS
------------------------
Use throw to create and throw exceptions.

Example:
    void divide(int a, int b) {
        if (b == 0) {
            throw runtime_error("Division by zero!");
        }
        cout << "Result: " << (a / b) << endl;
    }

    int main() {
        try {
            divide(10, 0);
        }
        catch (runtime_error &e) {
            cout << "Error: " << e.what() << endl;  // what() returns error message
        }
        return 0;
    }

2.3 MULTIPLE CATCH BLOCKS
--------------------------
Handle different types of exceptions.

Example:
    int main() {
        try {
            int choice;
            cin >> choice;
            
            if (choice == 1) throw invalid_argument("Invalid argument!");
            if (choice == 2) throw out_of_range("Out of range!");
            if (choice == 3) throw runtime_error("Runtime error!");
        }
        catch (invalid_argument &e) {
            cout << "Caught invalid argument: " << e.what() << endl;
        }
        catch (out_of_range &e) {
            cout << "Caught out of range: " << e.what() << endl;
        }
        catch (runtime_error &e) {
            cout << "Caught runtime error: " << e.what() << endl;
        }
        catch (exception &e) {
            cout << "Generic exception caught" << endl;
        }
        return 0;
    }

2.4 CUSTOM EXCEPTIONS
---------------------
Create your own exception classes.

Example:
    class MyException : public exception {
        string message;
    public:
        MyException(string msg) : message(msg) {}
        
        const char* what() const noexcept override {
            return message.c_str();
        }
    };

    int main() {
        try {
            throw MyException("Custom error message");
        }
        catch (MyException &e) {
            cout << "Custom error: " << e.what() << endl;
        }
        return 0;
    }

2.5 CATCH-ALL HANDLER
---------------------
Catch all exceptions using (...).

Example:
    int main() {
        try {
            throw 42;  // throw int
        }
        catch (...) {  // Catches any exception
            cout << "Unknown exception caught!" << endl;
        }
        return 0;
    }

2.6 NESTED TRY-CATCH
--------------------
Try-catch blocks can be nested.

Example:
    int main() {
        try {
            try {
                throw invalid_argument("Inner exception");
            }
            catch (logic_error &e) {
                cout << "Inner catch: " << e.what() << endl;
            }
            throw out_of_range("Outer exception");
        }
        catch (out_of_range &e) {
            cout << "Outer catch: " << e.what() << endl;
        }
        return 0;
    }

2.7 FINALLY-LIKE BEHAVIOR (RAII)
---------------------------------
C++ doesn't have finally, but uses RAII (Resource Acquisition Is Initialization).

Example:
    class ResourceManager {
    public:
        ResourceManager() { cout << "Resource acquired" << endl; }
        ~ResourceManager() { cout << "Resource released" << endl; }
    };

    int main() {
        try {
            ResourceManager rm;
            throw runtime_error("Something went wrong");
        }
        catch (exception &e) {
            cout << "Caught: " << e.what() << endl;
        }
        // Destructor called automatically
        return 0;
    }

2.8 NOEXCEPT SPECIFICATION (C++11)
-----------------------------------
Specify that a function doesn't throw exceptions.

Example:
    void safe_function() noexcept {
        cout << "This function doesn't throw" << endl;
    }

    void may_throw() noexcept(false) {
        throw runtime_error("May throw");
    }

    int main() {
        safe_function();
        return 0;
    }

2.9 COMMON STANDARD EXCEPTIONS
-------------------------------
exception              - Base class for all exceptions
logic_error            - Runtime logic error
invalid_argument       - Invalid argument passed
out_of_range           - Value outside expected range
runtime_error          - Generic runtime error
bad_alloc              - Memory allocation failure
bad_cast               - Invalid type cast
bad_exception          - Unexpected exception

Example:
    #include <stdexcept>

    int main() {
        try {
            vector<int> vec = {1, 2, 3};
            cout << vec.at(10);  // Throws out_of_range
        }
        catch (out_of_range &e) {
            cout << "Error: " << e.what() << endl;
        }
        return 0;
    }

3. COMBINING TEMPLATES AND EXCEPTIONS
===============================================================================

3.1 TEMPLATE FUNCTIONS WITH EXCEPTION HANDLING
-----------------------------------------------

Example:
    template <typename T>
    T safe_divide(T a, T b) {
        if (b == 0) {
            throw invalid_argument("Divisor cannot be zero");
        }
        return a / b;
    }

    int main() {
        try {
            cout << safe_divide(10, 2);    // Output: 5
            cout << safe_divide(10, 0);    // Throws exception
        }
        catch (invalid_argument &e) {
            cout << "Error: " << e.what() << endl;
        }
        return 0;
    }

3.2 TEMPLATE CLASS WITH EXCEPTION HANDLING
--------------------------------------------

Example:
    template <typename T>
    class Stack {
        vector<T> elements;
    public:
        void push(T value) {
            elements.push_back(value);
        }

        T pop() {
            if (elements.empty()) {
                throw underflow_error("Stack is empty!");
            }
            T value = elements.back();
            elements.pop_back();
            return value;
        }

        bool is_empty() const {
            return elements.empty();
        }
    };

    int main() {
        Stack<int> stk;
        try {
            stk.push(10);
            stk.push(20);
            cout << stk.pop() << endl;  // Output: 20
            cout << stk.pop() << endl;  // Output: 10
            cout << stk.pop() << endl;  // Throws exception
        }
        catch (underflow_error &e) {
            cout << "Error: " << e.what() << endl;
        }
        return 0;
    }

===============================================================================
4. BEST PRACTICES
===============================================================================

1. Use specific exception types rather than generic exception
2. Provide meaningful error messages
3. Avoid throwing exceptions in destructors
4. Use RAII for resource management
5. Specify noexcept when functions don't throw
6. Catch exceptions by const reference
7. Don't catch (...) unless you need to
8. Use templates for generic programming
9. Specialize templates only when necessary
10. Keep exception hierarchies simple and logical
